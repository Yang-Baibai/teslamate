 # TeslaMate 手机客户端使用说明（爱车车况）

 本手册面向最终使用者（你自己和家人），按"零基础也能照做"的口吻写。所有命令行都默认在 Windows 项目根 `C:\Users\<用户名>\OneDrive\文档\teslamate` 下执行；手机端不需要敲任何命令。

 ---

 ## 1. 准备（只需要做一次）

 电脑需要 24 小时开机跑 Docker，因为数据全在自家电脑上的 PostgreSQL 里；手机关电脑时 App 会显示"服务器离线"。

 App 与电脑之间有两种连法：家里 WiFi（最简单）和 Tailscale（外出/4G）。两种连法的"区别仅在地址栏填什么"，App 行为完全一致。

 | 场景 | 服务器地址 | 说明 |
 |---|---|---|
 | 家里，WiFi | `http://192.168.x.x:8090`（电脑的本机 IP） | 所有家里人都能用，不需要额外安装任何东西 |
 | 外出，4G | `http://<电脑的 Tailscale 名>:8090`（见 §6） | 出差或路上也可以看车况 |

 ---

 ## 2. 拿到地址与令牌（一次性）

 在电脑上：

 1. 查电脑的 WiFi IP：开始菜单 → 输入 `cmd` → `ipconfig` → 看"无线局域网适配器 WLAN / IPv4 地址"，比如 `192.168.1.20`。记下来。
 2. 查 API 令牌：项目根目录里有个 `.env` 文件，用记事本打开，复制 `API_TOKEN=` 后面的那串 48 位字符（比如 `48位十六进制字符串（示例占位，以 .env 实际值为准）`）。

 ---

 ## 3. 安装 App 到手机

 目标文件：`C:\tm-app\teslamate-app\app\build\outputs\apk\debug\app-debug.apk`（约 18 MB）。

 三种方式，挑一种：

 ### 3.1 USB 安装（最快）
 1. 手机开发者模式：设置 → 我的设备 → 全部参数与信息 → 连点 5 次"OS 版本"激活；返回进入"更多设置 → 开发者选项" → 同时打开 **USB 调试** 与 **USB 安装(允许通过 USB 安装应用)**。
 2. 手机用数据线连电脑，首次会弹"允许 USB 调试吗？"，勾选"始终允许"。
 3. 电脑 cmd 里：
    ```
    adb devices          # 看到 device 编号说明识别成功
    adb install -r "C:\tm-app\teslamate-app\app\build\outputs\apk\debug\app-debug.apk"
    ```
 4. 手机桌面上出现"爱车车况"。

 ### 3.2 网盘/聊天发送
 把 `app-debug.apk` 上传到微信/网盘给自己发一份，手机下载后点击安装（首次需要到"设置 → 应用 → 安装未知应用"里把对应 App 打开权限）。

 ### 3.3 Tailscale 出现后再决定（见 §6）
 如果你常用场景在户外，可以等装好 Tailscale 再一并调试。

 ---

 ## 4. App 首次配置

 1. 打开"爱车车况" → 底部导航切到 **设置**。
 2. 服务器地址：填 §2 拿到的 IP，例如 `http://192.168.1.20:8090`，**包含 `http://` 与端口**。
 3. API 令牌：粘贴 §2 复制的 48 位字符串。
 4. **测试连接**：成功会弹"服务器 v1 就绪"。失败按 §7 排查。
 5. 选择车辆：下拉里挑你的车，保存。
 6. 切回"车况"页：每 15 秒自动刷新。能看到电量环、续航、最近一次位置、温度即可。

## 5. 日常使用（5 个 Tab）

Tab 的数量和顺序这一版没变：**车况 / 充电 / 行程 / 统计 / 设置**。

| Tab | 主要看什么 | 备注 |
|---|---|---|
| **车况** | 电量环（含可用电量）、**真实可达续航**、里程表、车内外温度、空调状态、**海拔**、**四轮胎压**（俯视车图，异常轮标红）、当前位置（可展开地图） | 前台每 15 秒自动刷新；下拉刷新强制再拉一次；网络断会顶部红条；切回本页直接显示旧数据、后台再刷新，**不会闪骨架屏**；**首屏零滚动**（见下） |
| **充电** | 顶部「近 30 天」统计框 + 按月分组的充电记录；点开看**充电功率与电量曲线**、**充电损耗率**、**平均车外温度**、**充电桩类型** | 详情页是**两条折线**：充电功率曲线（kW）与电量曲线（%），横轴按真实时间展开 |
| **行程** | 顶部「近 30 天」统计框 + 按月分组的行程记录；点开有高德轨迹地图 + **功率剖面图** + 5 张详情卡 | 地图为静态图，**不支持手势缩放/拖动**；功率剖面图的横轴是**里程**不是时间（见下） |
| **统计** | 切「周/月/年」看里程柱图、充电量（直流 vs 交流）堆叠图、行车能耗趋势、电池健康曲线 | 周期口径：**周** = 含今天的近 7 个自然日，**月** = 近 30 个自然日，**年** = 近 12 个自然月（当月是进行中的数据）；全部自绘，零图表库 |
| **设置** | 服务器地址 / 令牌 / 测试连接 / 选车 / 版本号 | 换网络（如从家里 WiFi 切到 Tailscale）时改这里 |

> **图表已带屏幕阅读器描述**：电量环、能量条、俯视车图和每张图表都配了文字描述，
> 用 TalkBack 能听到「当前电量 XX%，正在充电」这类信息，不再是一张读不出来的图。

> **系统大字体也跟得上了**：以前 App 把系统字号封在 1.15 倍，用户在系统里把字调到最大，
> App 里几乎没变化。现在 **1.3 倍以内的系统设置完全生效**（再往上 App 仍会封顶 ——
> 车况页是仪表盘布局，字放到 2 倍会挤不下）。

### 车况页一屏能看到什么

车况页的顺序按「**先在一屏之内给出答案**」重排过，现在从上到下是：

1. 电量环 + **真实可达续航**
2. **位置**（地点名，点一下展开地图）
3. **空调 / 车内温度**
4. 能量条
5. 充电中 / 行驶中状态卡（没在充电、没在行驶就不显示）
6. 车外温度 / 功率
7. 海拔 / 可用电量
8. 胎压卡

**信息一条都没删**，只是把最常问的三个问题（还剩多少电、车在哪、空调开着吗）提到了最前面。
以前胎压卡和第三行信息块都排在折叠线以下——看不见等于没有。

### 行程详情里的「功率剖面」是什么

一条 **功率随累计里程变化** 的曲线，纵轴是电池净功率（kW）：

- **零线以上（蓝）= 耗电**；**零线以下（绿）= 能量回收**（松电门、下坡时把动能充回电池）
- **横轴是里程（km），不是时间** —— 这是刻意选的：
  - 堵车时车停着也在耗电，用时间轴画出来是"一大片低功率"，看着像省电了，其实是原地烧电；
  - 跑长途真正要判断的是"**还剩多少公里到下一个服务区**"，所以横轴必须是里程。
- 里程是按 GPS 点算出来的实际距离，**不是表显里程**，小数位可能和车上仪表略有出入。
- 服务端下发的轨迹点是抽样过的，App 内部按**每 1 公里取平均**再画，避免曲线抖动。
- 一条线同时说明能耗、地形、回收三件事：看到某段爬坡功率跳到 48 kW、
  下坡掉到 -60 kW，下次跑同一条高速就知道该注意哪一段。

### 几个容易看不懂的指标

**真实可达续航**：车况页那个续航数字**不是**车机标定的 EPA 续航（那个数夏季高速会乐观 25%~40%），
而是按你自己跑出来的实际能耗折算的：`标定续航 × 146 ÷ 实测 Wh/km × 温度修正 × 爬升修正 × 0.9`。
实测 Wh/km 由 App 用最近的行程按车速分桶取中位数算出来；
**行程样本不够时它会退回显示标定续航**，那时标题会写成「标定续航」而不是「真实可达」。

**充电损耗率** = (表计用电 − 实际充入) / 表计 × 100%。
电从电网到电池要经过充电桩和车上高压系统，这部分以热的形式损失掉了。
参考值：交流慢充 ~10%，直流快充 ~5%。**数值明显偏高（比如慢充超过 15%）可能意味着充电桩老化或线路接触不良**，值得留意。

**快充占比**：近 30 天充入电量里直流快充的百分比。占比高说明你主要依赖公共快充网络，长期成本会明显高于家用慢充。

**四轮胎压**：正常范围 **2.5–3.3 bar**（冷胎）。
当某个轮胎超出这个范围、或比另外三个低了 0.2 bar 以上时，App 会把该格标红并把标题变成「轮胎胎压 · 建议检查」。
（判定在**服务器端**做，App 只按结果标红——这样手机上的结论和微信推的告警永远一致。）
胎压异常通常在爆胎前几周就有苗头，值得每月看一眼。

> 为什么不是通用的 2.4–2.9：那个范围是网上抄来的，和这台车的实际工况对不上——
> 查了 51434 个真实采样点，本车范围是 2.50–3.30、平均 2.96 bar，
> 用 2.4–2.9 会有 **62% 的时间在误报**。一个天天误报的告警等于没有告警，
> 看到多了就会连真正的漏气信号一起忽略。换车的话这两个数值要按新车重新定。

### 车况提醒（不在 App 里，走微信/飞书）

**App 本身不发通知**——充电完成、胎压异常这些提醒，改由家里那台电脑上的
**Hermes**（绑定的微信或飞书）推送。所以：

- 想要提醒，先在**微信或飞书**里订阅那个机器人，别指望 App 会响
- 手机上不用开任何通知权限，App 是纯查看工具
- 想让提醒更准时，把 Hermes 设成"常驻"（微信/飞书机器人本来就一直在线）

**会推给你的四种情况**：

| 通知 | 什么时候发 |
|---|---|
| 🔌 开始充电 | 车从停着变成正在充电 |
| ✅ 充电完成 | 充完了，附带最终电量和充入量 |
| ⚠️ 胎压异常 | 某个轮胎超出正常范围，或比另外三只低 0.2 bar 以上 |
| ⓘ 数据长时间未更新 | 车辆超过 24 小时没有上报数据（车停着不动属正常） |

**看不到通知时的排查顺序**：

1. **车停着不动是正常的** —— 车熄火后不再上报数据，不会推"充电完成"这类消息。
2. **网络问题不算车况问题** —— 手机/电脑连不上时**不会**推送（推脚本读不到状态）。
   这时该看 App 里的红色错误提示条，而不是等通知。
3. **充电类消息要前后两次对比** —— 只在"状态发生变化"时推，
   所以一直停着的车不会反复刷屏。

### 电池健康度怎么算的？
**电池健康度（SOH）= 当前实测可用容量 ÷ 出厂标称可用容量 × 100%**

- **出厂标称可用容量**（分母）写在电脑项目目录的 `.env` 里，键名 `NOMINAL_BATTERY_KWH`。
  本车（Model 3 LR AWD Performance / P74D，**MY2022**，VIN 第 10 位 `N`）为 **78.4 kWh**（电池包总容量 82 kWh）。⚠️ 2026-10-25 修正：此前填的 76.8 kWh 是 2020/2021 款的容量。
- **当前实测容量**（分子）是 TeslaMate 根据每次充到 90% 以上时车机上报的标定续航反算出来的。

**所以「电池健康度 83.1%」= 相对出厂衰减了 16.9%。**
（App 早期版本在这里写「占铭牌 = 可用容量 ÷ 铭牌毛容量，两者不是同一口径，它不是衰减了多少」——
**那句话是错的**：`NOMINAL_BATTERY_KWH` 存的就是**出厂可用容量**，分子分母是同一口径，
比值就是衰减了多少。已在 v0.62.0 改正。）

为什么不用"历史最大值"当分母？因为历史最大值本身就是衰减后的测量值，会随时间往下漂，车越老分母越小，比值永远接近 100%，健康度会虚高好几个百分点（本项目曾因此显示 98%，实际应为 85%）。

**App 里「满电标定续航」那一行**：左边的 `446 km` 是车机自己报的读数，
右边括号里的 `538 km` 是**按出厂容量反推出来的同一刻度**数字，两边可以直接比。
⚠️ **官方标称续航（CLTC）不能直接和车机读数比** ——
官方那个数是**新车认证值**，不是这台车当前这把尺子上的读数
（车机读数是保守估计，低于认证值属正常）。
拿官方值去除车机读数，会得出「只剩七成」左右的**假结论**；
同刻度的真实比例是 **446 ÷ 538 = 82.9%**。

**换车时**：把 `.env` 里的 `NOMINAL_BATTERY_KWH` 改成新车的铭牌容量，重启 api 容器即可，App 端不用改代码。

常见特斯拉车型铭牌容量参考：Model 3 RWD/LR 约 60 kWh；Model 3 LR AWD Performance(P74D)、Model 3 Performance、Model Y Performance 约 76.8~78.4 kWh（2021 改款起为 78.4 kWh）；Model Y LR 约 60–62.5 kWh。具体以车辆铭牌或官网规格为准。

 ## 6. 装 Tailscale（外出也想看车）

 Tailscale 是 WireGuard 隧道，手机无论身处何地都能直接访问家里电脑 8090/3000/4000，无需做端口映射。

 ### 6.1 电脑上装
 1. 浏览器打开 https://tailscale.com/download/windows，下一步下一步装。
 2. 装完会自动在浏览器弹出登录页。**用任意非微信账号登录**（GitHub / 微软 / Google 都行）— 这一步需要你自己操作。
 3. 登录后，PowerShell 跑 `tailscale ip -4` 看 Tailscale IP（100.x.x.x），以及 `tailscale status` 看节点名。

 ### 6.2 手机上装
 1. 应用商店搜"Tailscale"安装（iOS / Android / 国内品牌商店都有）。
 2. 用 **同一账号** 登录。
 3. 进 App → 设置 → 服务器地址改成 `http://<电脑上 tailscale ip>:8090`（或 Tailscale 节点名 + MagicDNS）→ 测试连接 → 保存。

 之后无论手机在 4G/公司 WiFi/咖啡厅，Tailscale 全部走加密隧道互通，按流量计费 0 成本。

### 6.3 手机端省电豁免（外出时 App 连不上服务器）

手机系统的「省电 / 后台限制」会在息屏后**冻住 Tailscale 的 VPN**。
外网（4G / 公司 WiFi）时的表现是：**手机能上网页，但 App 连不上家里电脑** ——
因为网页走的是公网，App 走的是被冻住的隧道。

**手机接上 USB（开「USB 调试」）后，一次配好：**

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
$dev = '<真机序列号>'        # 换成你自己手机的 adb 序列号
& $adb -s $dev shell dumpsys deviceidle whitelist +com.teslamate.app
& $adb -s $dev shell dumpsys deviceidle whitelist +com.tailscale.ipn
& $adb -s $dev shell cmd netpolicy add restrict-background-whitelist 10283   # 爱车车况 uid
& $adb -s $dev shell cmd netpolicy add restrict-background-whitelist 10267   # Tailscale uid
& $adb -s $dev shell am set-inactive com.teslamate.app false
& $adb -s $dev shell am set-inactive com.tailscale.ipn false
```

| 命令 | 作用 |
|---|---|
| `dumpsys deviceidle whitelist +` | **Doze 白名单** —— 息屏后不被系统冻住 |
| `cmd netpolicy add restrict-background-whitelist <uid>` | **后台流量豁免** —— 不被「省流量」掐断 |
| `am set-inactive <包名> false` | 不被判为「不活跃应用」而回收 |

uid 的查法：`adb shell dumpsys deviceidle whitelist` 里那行 `user,<包名>,<uid>` 就是。

> ⚠️ 这些设置**可能被系统升级或「清除数据」重置**，重置后重跑一遍即可。
> 不想用 adb 的话，在手机上设等价项：
> **设置 → 应用 → 爱车车况 / Tailscale → 电池 → 「无限制」+「允许后台活动」+「允许自启动」**。

✅ **本机已于 2026-10-25 实测配好**（Redmi 25042PN24C / HyperOS）：
Doze 白名单含 `com.teslamate.app` 与 `com.tailscale.ipn`，
后台流量白名单含 uid 10283 / 10267，VPN provider 正常在跑。

 ## 7. 常见问题

 | 现象 | 排查顺序 |
 |---|---|
 | 测试连接一直转圈 | 1) 地址没写端口（必须 `:8090`）；2) 手机和电脑不在同一 WiFi；3) 电脑防火墙阻挡入站 8090（控制面板 → Windows Defender 防火墙 → 高级设置 → 入站规则 → 新建端口 TCP 8090） |
 | 测试连接报 401 | App 设置页的 Token 字符串与电脑 `.env` 的 `API_TOKEN=` 后半段不一致；改完电脑要 `docker compose up -d api` 让容器拿到新 Token |
 | 测试连接通过，但所有页面空 | URL 漏 `http://` 或端口；检查底部"服务器 v1 就绪"是否真的提示过 |
 | 地图加载出空白/有偏移 | 地图是**你的服务器**向高德申请的静态图，需要手机能连上服务器、服务器也能访问高德；在海外或公司网有代理阻断时，把手机 WiFi 切到 4G 试一次 |
| 地图加载失败，提示「请检查网络后下拉重试」 | 同上（手机↔服务器、服务器↔高德两条链路都得通）；关掉 VPN / 代理再试，然后下拉刷新重试 |
 | 车况页一直"在线→休眠→在线"闪跳 | 车辆真的在休眠唤醒之间（正常），间隔 15 秒即可看到刷新 |
 | App 提示"网络错误"但网页能开 | 通常是手机切了网络、或者电脑 Docker Desktop 重启后还没 healthy；等 30 秒再看 |
| 外出（4G / 公司 WiFi）时 App 连不上服务器，但网页能开 | **Tailscale 的 VPN 被系统省电冻住了** —— 用 USB 连电脑按 [6.3](#63-手机端省电豁免外出时-app-连不上服务器) 配一次 Doze / 后台流量白名单 |

 ## 8. 升级 App

 从 v0.1.4 起，**App 启动时会自动检查更新**：
 1. 打开 App → 后台自动拉一次 `/api/v1/app/latest`。
 2. 若发现 `version_code > 当前 App versionCode`，会弹"发现新版本 v0.1.X"对话框，附带更新说明。
 3. 点 **"立即更新"** → 系统下载 UI 出现 → 完成后自动跳安装界面（首次会弹"允许安装未知应用"权限引导）。
 4. 装完启动 App → 不会再弹（已对齐最新版本）。
 5. 想下次再升也行：点 **"稍后"** 关掉弹窗，下次冷启动再查。

 ⚠️ **必须杀掉旧 App 进程**才能触发新版本检查：MIUI 上把 App 划掉再点开才算冷启动；从最近任务切回来不会重查。

 💡 想知道"现在装的是哪个版本"：App 设置页里会显示（v0.1.4 起），对比服务器上的 `/api/v1/app/latest` 一眼就清楚。

 ---

 ## 9. 卸载

 手机上长按 App 图标 → 卸载即可，所有本地设置也会一起清掉。docker 侧的容器（database/mosquitto/teslamate/grafana/api）与数据均不受影响。

 ---

 ## 10. 反馈与日志

 - 电脑端看 API 日志：`docker compose logs -f --tail 100 api`
 - 电脑端看采集器日志：`docker compose logs -f --tail 100 teslamate`
 - 手机端看不到错误时：App 设置页有"上报问题"，未来版本会加；目前遇到问题请直接给电脑反馈截图即可。

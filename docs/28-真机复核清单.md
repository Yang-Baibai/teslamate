# 真机复核清单（v0.85.0 起）

> **为什么有这份清单**：2026-10-29 接上 USB 做真机复核时发现，
> 「模拟器能测什么、真机才能测什么」这件事每轮都在重新想。
> 而**版面类**问题如果不在模拟器上用**受控注入**造最坏情况，
> 就会一路拖到发版才暴露（这轮就抓到一个「左前窗开着」被砍成「左前窗开...」）。
>
> ⇒ 照着这份清单走，每轮只花十几分钟。

## 一、两台设备各管什么

| 设备 | 负责 | 不负责 |
|---|---|---|
| **模拟器** `emulator-5554` | **版面**：与真机同参数（1440×3200@600 = 384dp 宽）⇒ 版面问题在这里就能复现；还能用**受控注入**造最坏情况 | 系统级差异（ROM / 深色 / 真实网络） |
| **真机** `<真机序列号>` | **系统级**：真实 ROM（后台杀）、深色模式、真实网络路径（Tailscale / MagicDNS）、真实安装升级 | 造极端数据（慢、且不该在生产数据上动手脚） |

连续八轮（v0.93.0 ~ v0.103.0）没有真机视觉复核的根因，**不是**「模拟器崩在 WHPX 初始化」那么简单：

| 证据 | 含义 |
|---|---|
| `emulator -accel-check` → 「WHPX is installed and usable」 | 这只是**静态能力检查**（WHPX API 在），**不代表**加速器真的可用 |
| `systeminfo` → 「A hypervisor has been detected」 | **Windows 自己的 hypervisor 正占着 CPU** |
| `HKLM\...\DeviceGuard\EnableVirtualizationBasedSecurity = 1` | VBS **开着** |
| `HKLM\...\DeviceGuard\HyperVVirtualizationBasedSecurityOptout = 0` | **没退出** VBS |
| `HKLM\...\Scenarios\HypervisorEnforcedCodeIntegrity\Enabled = 0` | 内存完整性（HVCI）已关 ✔ |

⇒ **关掉内存完整性不够**：VBS/Hyper-V 仍在运行 ⇒ hypervisor 被它占着 ⇒
WHPX 拿不到加速器 ⇒ **guest 内核根本不启动**
（症状：`-show-kernel` 零内核输出、`qemu` 进程 0.1 秒 CPU / 116 MB、`adb` 永远 `offline`）。

⇒ **要彻底修好模拟器，需要管理员 + 再重启一次**：

```powershell
bcdedit /set hypervisorlaunchtype off        # 让 Windows 不再启动自己的 hypervisor
# 再到「Windows 功能」里关掉：Hyper-V、虚拟机平台、Windows Hypervisor 平台（WSL2 需要的话除外）
# ⇒ 重启
```

### ✅ 2026-11-11 就地订正：**模拟器已经能起来了** —— 真因是 **SDK 根路径含中文**，不是宿主虚拟化

> ⚠️ 上面那些排查（VBS / HVCI / `HypervisorPlatform` 的 State / `bcdedit`）**都不是本问题的根因**。
> 真因是**路径** —— 而且**不需要管理员、不需要重启、不用改任何宿主配置**。

**根因**：本机用户名是「<用户名>」⇒ 默认 SDK 根 `C:\Users\<用户名>\AppData\Local\Android\Sdk` **含非 ASCII 字符**；
在这个路径下启动 emulator，**无论换什么参数都起不来**（崩 / 永久 offline / 进程静默退出，三种形态）。
把 emulator 放到**纯 ASCII** 的 `C:\tm-sdk` 下启动 ⇒ **一次就成**。

| # | emulator 所在路径 | 包版本 | 快照 | 环境变量 | 结果 |
|---|---|---|---|---|---|
| ① | `C:\Users\<用户名>\...` | 37.2.12 | 开 | 无 | 崩：0xC0000005 访问冲突 |
| ② | `C:\Users\<用户名>\...` | 37.2.12 | 关 | 无 | 永久 `offline`（qemu CPU 0.6 秒 = 阻塞） |
| ③ | `C:\Users\<用户名>\...` | **37.2.13** | 关 | 无 | 永久 `offline` ⇒ **换包不是解药** |
| ④ | `C:\Users\<用户名>\...` | 37.2.13 | 关 | **有**（`ANDROID_SDK_ROOT` 等） | 进程死、设备消失 ⇒ **加环境变量也没用** |
| ⑤ | **`C:\tm-sdk`（纯 ASCII）** | 37.2.12 | 关 | 有 | ✅ **46.8 秒启动成功** |

⇒ **唯一决定性变量 = 路径是不是纯 ASCII**（包版本 / 快照 / 环境变量 / 加速模式 / AVD / 镜像，逐个排除）。

**产物证据（2026-11-11 00:38~01:05 实测）**：`adb devices` ⇒ `emulator-5554 device`；
`getprop sys.boot_completed` ⇒ **1**；启动耗时 **16.5~46.8 秒**；`wm size/density` ⇒ **1440×3200 / 600**（= 384dp 宽，与真机同参）；
qemu 命令行里带 **`-enable-whpx`**（⇒ **WHPX 加速真的在工作**，不是 TCG 慢速兜底）；截图能取。

=> **模拟器不等宿主重启就能用** ⇒ 「先重启再验证」这一步**可以跳过**
（`HypervisorPlatform` 那个 DISM 变更继续留着也无妨：它只**启用**、不**关闭**任何东西）。

**怎么起（一条命令）**：

```bash
bash scripts/start-emulator.sh          # Git Bash
pwsh -File scripts/start-emulator.ps1    # PowerShell
```

脚本自己会：建/校验纯 ASCII 的 SDK 根（`C:\tm-sdk`，其余目录用**联接**指回真实 SDK）→
清理残留实例与锁 → 启动 → **等 `sys.boot_completed=1`** → 打印产物证据（设备状态 / boot 耗时 / 屏幕参数 / 加速方式 / 截图路径）；
失败时把关键日志行打出来。

⚠️ **两个会把调用方吊住的坑（脚本里已绕开）**：
1. `Start-Process -RedirectStandardOutput` 在 PS7 里给的是**管道**（不是文件），pwsh 退出时要等管道 EOF
   ⇒ **常驻的 emulator 会把调用方吊住**（脚本跑完了、调用方却不返回）
   ⇒ 改成 **cmd 自己把输出重定向到文件 + ShellExecute 启动**（子进程不继承调用方句柄）；
2. **adb 的 stdout 不能接进 PowerShell 管道**（`| Out-String`）：adb 守护进程继承管道写端 ⇒ 等不到 EOF
   ⇒ 一样吊住 ⇒ 一律**让 adb 写文件再读**。

## 四、什么该用真机查（模拟器查不到）

- **ROM 杀后台**：国产 ROM 会杀后台进程 ⇒ 依赖后台任务的功能（主动通知）必须真机验；
- **真实网络路径**：App 配的是 `<主机名>:8090`（**MagicDNS 直连**，不经 adb reverse）⇒
  外出时靠 Tailscale（手机上的 Tailscale **可能没连**）；
- **安装 / 升级 / 签名**：分发包换版前必须 `apksigner verify --print-certs` 比证书；
- **系统级交互**：深色模式、字体缩放、通知权限、后台存活。

## 五、踩过的坑（别再踩）

| 坑 | 真相 |
|---|---|
| `adb` 报「more than one device」 | 两台都在 ⇒ 显式 `-s <device>` |
| `adb shell input text` 之前必须 `input tap` | 不先点，文字进不去 |
| 手机 ping 不通 PC | **不代表 TCP 不通**（防火墙挡 ICMP）⇒ 用浏览器开 API 实测 |
| `aapt` 读 APK 报「找不到 AndroidManifest.xml」 | **路径有中文**（`%TEMP%` 也在中文用户目录下）⇒ 复制到 `C:\tm-app\` 这种纯 ASCII 路径 |
| `settings put font_scale` 之后 App 没了 | Android 的配置变更会**杀进程** ⇒ 不是崩溃，别误判 |
| uiautomator dump 偶尔只 dump 到桌面 | App 刚被 force-stop / 切到桌面 ⇒ 重启 App 再 dump |
| Python 内联命令里带中文路径 | PowerShell 会重编码 ⇒ **一律写临时 .py 文件** |
| 模拟器的底部「Home 键」吃掉 tab 坐标 | 模拟器是 **3 键导航栏**，Tab 栏真实 bounds 是 `y≈2720~3020`，而真机是手势条 ⇒ **沿用真机的 `y=3050` 会 tap 到 Home 键**，App 直接退回桌面（截图全是桌面图标，还以为 App 没启动） ⇒ tap 前先 `uiautomator dump` 找 Tab 的**真实 bounds** |
| 小米手机上 `adb install` 报 `INSTALL_FAILED_USER_RESTRICTED` | MIUI 自己的一套「**USB 安装**」开关（开发者选项里）挡着，**手机上不会弹框**、直接秒失败 ⇒ 开那个开关；或绕开安装界面：`adb push x.apk /data/local/tmp/` + `adb shell pm install -r -g /data/local/tmp/x.apk` |
| 模拟器起来后 `adb` 永远 `offline`、qemu 只有 0.1 秒 CPU | **有僵尸实例占着 AVD 锁** ⇒ 无头模式的进程名是 **`qemu-system-x86_64-headless.exe`**，`taskkill /IM qemu-system-x86_64.exe` **杀不掉它** ⇒ 后续每次启动都只报「Another emulator instance is running」并立刻退出 ⇒ 按**名字包含 qemu/emulator** 枚举后逐个杀，再删 AVD 目录里的 `*.lock` 与 `read-snapshot.txt` |
| 模拟器启动后卡在 "accelerator is operational" 不动 | ⚠️ **2026-11-11 订正：真因不是 WHPX 功能没启用，而是 SDK 根路径含中文** ⇒ 换到纯 ASCII 路径（`C:\tm-sdk`）就起来了（16~47 秒，`-enable-whpx` 加速在用）⇒ 见上文第一节末尾；`-accel-check` 说 "usable"、日志说 "accelerator is operational" **都只是代理信号**，不能当「guest 能用」的证据 |
| **模拟器在任何参数下都起不来**（崩 / 永久 offline / 进程静默退出） | ⚠️ **2026-11-11 实测真因：emulator 所在的 SDK 根路径含非 ASCII 字符**（本机用户名「<用户名>」）⇒ 换到**纯 ASCII** 的 `C:\tm-sdk` 启动即可 ⇒ 换包 / 设环境变量 / 换 AVD / 换加速模式**都无效** ⇒ 一条命令：`bash scripts/start-emulator.sh` |
| `Start-Process -RedirectStandardOutput` 之后**调用方一直不返回** | PS7 给子进程的是**管道**（不是文件），pwsh 退出时要等管道 EOF ⇒ **常驻进程（emulator）把它吊住** ⇒ 改成 **cmd 自己把输出重定向到文件 + ShellExecute 启动**；同理 **adb 的 stdout 别接进 PowerShell 管道**（守护进程继承写端 ⇒ 等不到 EOF）⇒ 一律**写文件再读** |
| 模拟器传 `-gpu swiftshader` 反而起不来 | 那条老路径要 `opengl32sw.dll`，本机 SDK **没有这个文件** ⇒ 「Failed to load opengl32sw ⇒ 回退系统 OpenGL」⇒ guest 起不来 ⇒ **别传 `-gpu`**，用 AVD 自带的 `hw.gpu.enabled=no`（走 `lib64/gles_swiftshader` 的 gfxstream 路径） |
| `adb shell content query --uri content://com.mobilerun.portal/ping` 报「Accessibility service not available」 | Portal 装了、ContentProvider 也活着，只是**无障碍服务没被系统绑定** ⇒ MIUI 会**静默过滤** adb 写入的 `enabled_accessibility_services` ⇒ 要在手机「设置 → 无障碍 → 已下载的服务」里**手动打开 Mobilerun Portal**（或开「USB 调试（安全设置）」） |
